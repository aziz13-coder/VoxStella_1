# Mundane Framework And Revolution Inventory

Date: 2026-04-13

## Purpose

This inventory closes Phase D of the gap-narrowing plan.

It records which framework and revolution layers are already justified by the local corpus, which ones are already represented in the runtime, which additions are runtime-worthy next, and which candidates remain explicitly not justified for promotion.

## Current Runtime Framework Stack

The current mundane runtime already supports a real layered framework, even if the surface chart list remains deliberately narrow.

### Live Chart Families

- `aries_ingress`
- `lunation`
- `eclipse`
- `war_event`
- `national_chart`

### Live Framework Layers

- annual Aries ingress
- active quarterly ingress context for:
  - Aries ingress output
  - lunation output
  - eclipse output
- long-cycle Jupiter-Saturn backdrop
- national-chart structural overlay
- war-event anchor for exact hostilities

This is stronger than the old runtime state, which effectively treated the Aries ingress as a single isolated annual chart and left much of the broader revolution hierarchy implicit.

## Doctrine Inventory From Local Sources

The current local corpus supports the following hierarchy.

### Strongly Supported

1. Aries ingress as the principal annual mundane chart
2. other cardinal ingresses as subordinate framework refinements
3. lunations as shorter windows inside the annual framework
4. eclipses as intensified trigger charts that can override or sharpen a shorter window
5. annual revolutions divisible into shorter operative segments
6. mutation / conjunction cycles as longer collective backdrops
7. exact event charts for wars and other timed openings
8. national charts as durable polity structure and validation overlays

### Sources Already In The Repo

- Green / Raphael / Carter:
  - annual and quarterly ingress doctrine
  - lunation window doctrine
  - eclipse priority and visibility doctrine
- Bonatti:
  - revolutions may be divided into halves and quarters
  - locality and clime modify how testimony extends
- Watters:
  - mutation charts and long-cycle backdrop
  - event charts should still be checked against national charts when available

## What The Runtime Now Represents Adequately

These items are already strong enough to remain live.

### Adequately Represented

- annual Aries ingress
- active quarterly ingress as framework context
- lunation inside annual/quarterly backdrop
- eclipse inside annual/quarterly backdrop
- mutation / conjunction cycle as background trigger family
- war-event anchor for outbreak semantics
- national-chart overlay for polity structure

## Runtime-Worthy Additions Next

These are the additions the current corpus can justify next, but they should still be benchmark-seeded before promotion.

### Shortlist

1. explicit quarterly-ingress benchmark pack
   - not a new chart family first
   - first a benchmark slice proving that quarterly ingress context materially changes interpretation

2. stronger revolution-subperiod benchmark pack
   - use the Bonatti division doctrine as the seed
   - prove that subperiod language is doing work beyond generic window splitting

3. tighter framework hierarchy exposure in output
   - annual framework
   - active quarterly framework
   - trigger chart
   - long-cycle backdrop

This would improve transparency without adding a new chart type immediately.

## Not Yet Justified For Runtime Promotion

These remain out of bounds for now.

### Not Yet

- a generic `revolution` chart type exposed in the UI
- half-year and quarter-year runtime charts as separate user-selectable families
- monthly revolution families beyond lunations
- progressed mundane overlays as first-class runtime charts
- battle-chart or accession-chart families as a broad generic runtime class
- country-sign transit as a new chart family instead of a doctrine/tooling concept

The reason is not lack of interest. The reason is that the current local corpus does not yet support benchmark-seeded runtime promotion cleanly enough.

## Practical Runtime Position

The current runtime should be described as:

- framework-layered
- doctrine-backed
- still intentionally conservative on chart-family proliferation

That is the correct posture.

The gap was not that the runtime had too few labels. The gap was that the framework hierarchy was under-expressed.

That hierarchy is now materially better represented through:

- annual ingress context
- active quarterly ingress context
- long-cycle backdrop
- event-chart and national-chart role separation

## Decision

Phase D closes with this bounded conclusion:

- do not add a new broad revolution chart family yet
- keep the runtime chart list stable
- treat the next work as benchmark-first, not UI-first

That is the only clean way to widen framework handling without reintroducing semantic blur.
