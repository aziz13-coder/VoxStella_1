## Guide Boundaries

To keep the docs clean, each guide should answer a narrow question.

- The Astro Clock overview should explain the workspace, Realtime versus Manual, saved snaps, and how snaps feed the deeper tools.
- The Saved Snaps guide should explain snap creation, list view, search mode, local storage, and which features require or reuse snaps.
- The Aspect Analysis guide should explain the modal, its filters, and the three main reading groups: planetary, declination or antiscia, and cusps.
- The Synastry guide should explain the two-snap workflow, scope toggles, overall compatibility, and relationship signature outputs.
- The Election guide should explain the model picker, shared scan controls, natal source options, ranked results, and jump or export actions.
- The Transits guide should explain manual natal versus saved snap, context windows, scan windows, exact-time computation, and predictor output.
- The Astrocartography guide should explain the required natal snap, the map-first workflow, city inspection, and the report workspace.
- The Astrocartography PathFinder guide should explain goal families, atlas filters, progress behavior, and how to work from shortlist to inspected city.
- The Trait Profile guide should explain chart-driven profile output, filters, source layers, topic maps, house influence, and AI-prompt copying.
- The Forensic guide should explain the finding stack, case-profile controls, investigative sections, abduction mode, and report export.

## Source-Checked Feature Rules

These rules are the main guardrails for the docs.

- Saved snaps are chart snapshots, not screenshots.
- Loading a snap moves Astro Clock into Manual mode using the snap's stored chart context.
- Synastry requires two saved snaps.
- Transits can use manual natal input or a saved snap as the natal source.
- Astrocartography requires a saved natal snap.
- Election can run without a saved snap, but supported matters can use a saved snap for natal overlay or promise checks.
- Trait Profile and Forensic work from the active Astro Clock chart, so loading a snap first changes what they read.

## Recommended Build Order

1. Keep the Astro Clock overview short and centered on saved snaps and workspace flow.
2. Keep each feature guide separate instead of merging modal details back into the overview.
3. Extend the set only with focused supplements once a screenshot or source-backed reason exists.
4. Reuse the same snap-dependency language across every Astro Clock page so the workflow stays consistent.
